Installation

Pure Python with three dependencies. No build step, no GPU, no ROS.

git clone https://github.com/error404-wq/vio_simulator.git
cd vio_simulator
pip install numpy scipy opencv-python

Tested on Python 3.10+. The browser build runs the identical sim/ package through PyScript, so results match.

Quick start

Render one frame with its exact depth map:

import numpy as np
from sim.scene import Camera, render
from sim.worlds import corridor, add_obstacles
from sim.trajectory import Trajectory

cam   = Camera.davis346(noise_std=5.0, use_fisheye=True)
scene = add_obstacles(corridor(seed=42), count=8, seed=142)
traj  = Trajectory(peak_omega=4.0, omega_hz=0.6, speed=6.0)

R = traj.rotation(np.array([0.5]), duration=2.0)[0]   # world-from-camera
p = traj.position(np.array([0.5]))[0]

image, depth = render(scene, cam, R, p)
print(image.shape, depth.shape)
print('depth range:', np.nanmin(depth), '-', np.nanmax(depth), 'm')

depth is metric, per-pixel, and analytic. Pixels seeing no surface are +inf.

Adding motion blur

from sim.sensors import render_blurred

image, depth = render_blurred(scene, cam, traj, t_center=0.5,
                              exposure=0.010, n_samples=8, duration=2.0)

Blur is produced by integrating n_samples true sub-exposures across the shutter. Raise it for smoother blur at higher cost; 8–16 is usually plenty.

Scenes

A scene is a list of textured planes. Planarity is what buys closed-form depth, so it is a deliberate constraint rather than a shortcut. 

from sim.worlds import corridor, add_obstacles, natural_texture

scene = corridor(length=30.0, width=6.0, height=3.0, seed=0)
scene = add_obstacles(scene, count=10, seed=7)

Custom geometry is a plane with two spanning vectors, in metres:

import numpy as np
from sim.scene import Plane

wall = Plane(
    origin=np.array([-3.0, -1.5, 12.0]),
    u_axis=np.array([6.0, 0.0, 0.0]),    # width
    v_axis=np.array([0.0, 3.0, 0.0]),    # height
    texture=natural_texture(512, alpha=1.2, seed=3),
    name='back_wall')
scene.add(wall)

natural_texture synthesises a 1/fα spectrum, which matches natural image statistics — so corner density and tracking behave realistically. Checkerboards and white noise do not.

Trajectories

Trajectories are defined by their angular velocity, which is then integrated on SO(3). That is what makes peak angular rate an independent variable you can sweep, and it means ground-truth angular velocity is exact rather than differentiated from poses. 

traj = Trajectory(
    peak_omega=8.0,       # rad/s — the variable to sweep
    omega_hz=0.6,         # how fast the manoeuvre oscillates
    speed=12.0,           # m/s forward
    lateral_amp=0.6,
    broadband_rms=0.47,   # realistic high-frequency content, rad/s RMS
)

broadband_rms adds attitude-loop and airframe content above 5 Hz. Real racing drones carry roughly 0.47 rad/s RMS there. Leave it at zero for a clean analytic manoeuvre; set it when high-frequency realism matters.

Camera & lens

cam = Camera.davis346(noise_std=5.0, use_fisheye=True)
print(cam.K)                       # intrinsics
print(cam.width, cam.height)       # 346 x 260

Lens model matters more than people expect. With use_fisheye=True the camera is equidistant with a ~115° horizontal field. Applying a pinhole intrinsic to those pixels is a real and easy mistake — in our own earlier analysis it inflated measured rotation error by 61–73%. Undistort into normalised coordinates before doing geometry.

Inertial data

from sim.trajectory import ImuModel

imu = ImuModel(rate_hz=1000.0, gyro_noise_density=0.043).sample(traj, duration=2.0)

imu['t']           # timestamps
imu['gyro']        # measured, corrupted
imu['gyro_true']   # exact truth
imu['gyro_bias']   # the bias walk actually injected
imu['accel'], imu['accel_true']

Because the injected bias is returned, an estimator can be scored against exactly what it was asked to recover — not against an approximation of it.

Event camera

from sim.sensors import simulate_stream

data = simulate_stream(scene, cam, traj, duration=1.0,
                       frame_hz=30.0, event_render_hz=2000.0,
                       contrast_threshold=0.20)

data['frames'], data['depths']                      # synchronised frames + exact depth
data['ev_x'], data['ev_y'], data['ev_t'], data['ev_p']   # event stream

The event model is not calibrated against a real sensor. Its threshold, refractory period and jitter are plausible defaults. Treat conclusions that hinge on those parameters as assumptions — see Validation.

Parameter sweeps

The reason to use a simulator: change one thing and hold everything else exactly fixed.

for peak in [1.0, 2.0, 4.0, 8.0, 12.0]:
    traj = Trajectory(peak_omega=peak, omega_hz=0.6, speed=6.0)
    img, depth = render_blurred(scene, cam, traj, 0.5,
                                exposure=0.010, n_samples=8, duration=2.0)
    # scene, texture, seed, lens and noise are unchanged;
    # only angular rate differs, so any difference is attributable to it.
